# PURPOSE

Admin can:

1. See who performed an action
2. See what action was performed
3. See when it happened
4. See which module was affected
5. Search logs
6. Filter logs
7. View detailed activity
8. Export logs

# WHAT SHOULD BE LOGGED?

Don't log every tiny UI interaction.
Log important events such as:

Authentication
User logged in
User logged out
Failed login
Password changed
Account suspended

Students
Student created
Student updated
Student deleted

Marks
Marks added
Marks updated
Marks deleted

Attendance
Attendance recorded
Attendance modified

Fees
Payment recorded
Fee updated
Fee status changed

Library
Book added
Book issued
Book returned
Book deleted

Users
User created
Role changed
Permission changed
Account deactivated

# BEFORE & AFTER CHANGES ⭐

For important updates, store the difference:
FIELD              BEFORE       AFTER

Email              old@email    new@email
Semester            1            2
Attendance          82%          85%

This is a strong professional feature.

# FAILED ACTION

If an operation fails:
⚠️ Failed

Admin attempted to delete Book B001.

Reason:
Book currently has active borrowers.

This is useful for debugging and security auditing.

# SECURITY

Audit logs should be:

Visible only to authorized administrators
Difficult for normal users to modify
Timestamped automatically
Associated with the authenticated user
Stored separately from ordinary UI state

For your project, don't give ordinary students or teachers access to audit logs.
