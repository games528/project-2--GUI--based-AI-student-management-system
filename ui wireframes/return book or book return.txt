THIS SCREEN HANDLES RETURNING AN ISSUED BOOK AND UPDATING THE LIBRARY INVENTORY.

# PURPOSE

Admin/library staff can:

1. Search active book transactions
2. Find a borrower
3. See issued books
4. Record return
5. Automatically update available copies
6. Detect overdue books
7. Calculate optional fines
8. Generate return receipt

# SEARCH

The librarian should be able to search using:
🔍 Search by:

Student Name
Student ID
Book Title
Book ID
Issue ID

Example:
Search: STU2026001

→ Rahul Kumar
   Python Programming
   Issue ID: LIB-2026-0042

# ACTIVE BORROWING LIST

If the student has multiple books:

Rahul Kumar — Active Books

┌────────────┬─────────────────────┬────────────┬────────────┐
│ Issue ID   │ Book                │ Due Date   │ Status     │
├────────────┼─────────────────────┼────────────┼────────────┤
│ LIB-0042   │ Python Programming  │ 08 Aug     │ 🔴 Overdue │
│ LIB-0045   │ DBMS Fundamentals   │ 18 Aug     │ 🟢 Active  │

Clicking a row selects it for return.

# RETURN DATE

Default to today's date:

Return Date
[ 09/08/2026 📅 ]

# OVERDUE DETECTION ⭐

The system compares:
Return Date
      vs
Due Date

Example:
Due Date:     08/08/2026
Return Date:  09/08/2026

→ 1 day overdue

Display:
🔴 OVERDUE — 1 DAY

If returned on time:
🟢 Returned on time

# FINE CALCULATION

Make this optional.
Example configuration:
Fine Rate = ₹10/day

Then:
1 day × ₹10 = ₹10

Display:
Fine: ₹10

Don't hard-code the fine into the UI. Later, put the rate in Settings.

# DATABASE CHANGES

Suppose before return:
Total Copies     = 10
Available Copies = 6
Issued Copies    = 4

After returning one book:
Total Copies     = 10
Available Copies = 7
Issued Copies    = 3

The transaction itself changes from:
Status = Issued

to:
Status = Returned
Return Date = 09/08/2026

# VALIDATION

Check:

1. Transaction exists
2. Book is currently issued
3. Return date isn't before issue date
4. Book isn't already returned
5. Fine calculation is correct
6. Inventory count doesn't exceed total copies
